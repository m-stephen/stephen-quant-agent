## 实现与验证边界

1. `flow_response_protocol.py` 固定候选包、全部 23 项预算、控制组、成本和筛选要求。配置经过 JSON 往返仍有相同规范哈希。变更预算、债务、成本、日历、候选或命中 tombstone 在创建数据库前拒绝。
2. 跨成本共享先完成源 Trial 的两年实际拟合，再把同一模型文件绑定到另一成本 Trial。除成本和账户名称外契约必须相同；验证实际文件、历史矩阵、日历及原生拟合时间。不把两次绑定说成两次独立训练。
3. `VerifiedHistoryCache` 在一个进程里仅解码一次已绑定的历史矩阵，嵌套映射/列表不可正常修改。每次使用仍检查来源关系、历史文件及所有 bundle 的实际 SHA-256；不接受任意调用方 `.get()` 对象。此优化减少 JSON 解析，不承诺消除哈希 I/O，也不是多用户安全系统。
4. `load_original_targets` 从原目标位置读取实际字节，检查原卡和目标文件/规范哈希。后端逐字节保存旧 lowvol/stable 目标。合成测试使用合成原目标；本轮没有读取真实旧目标数值。旧目标用 full_target、新策略用 target_changes，都运行在已披露的 B3 保守 bar 上，不能称为与旧账户结果逐字节相同的重放。
5. `audit_response_account` 不调用执行引擎、选股器或收益汇总函数，按源开盘价与成交重建股份、费用、现金，再以收盘价/停牌/20 日核销重建净值、年度收益和夏普。限价/容量、时间、现金、成交、估值和费用篡改测试均被拒绝。**它尚未独立证明原始源字段、模型训练、目标选择或 target_changes 调度的正确性**；结果明确标记这部分未完成。
6. `workflows/flow_response_epoch.py` 串起全量已预留实验：校验原生完整 spec → 独占后端标记 → 原目标 → 历史特征 → 14 个拟合/28 个绑定 → 22 个账户 → 独占 RESULT。失败保留全部预留和 ABORTED，重复调用不覆盖旧证据。该后端不是正式市场入口：跨操作独占 claim、固定父证据/运行代码和 GitHub 预登记验证仍需外层实现。
7. 即使账户数字好看，后端仍写 `COMPLETE_PENDING_INDEPENDENT_AUDIT`、独立源/模型/目标审计 NOT_RUN、`validated_alpha=false`。DSR/PBO/placebo 是 null/NOT_RUN，不伪造为通过。

## 本轮测试与规模

最终针对性测试：62 passed，159.39 秒；完整回归、JUnit 哈希及 CI 状态见 `V11_21_VERIFICATION.md`。首轮完整实验后端已执行成功，但测试断言错误地直接查询了不存在的账本列；现改为原生 `fit_lineage()` API。初始 1 failed/6 passed 的 JUnit 保留，不能混入通过总数。

完整合成夹具包含 80 股票、550 个工作日（不是交易所节假日日历），2022 年训练、2023/2024 连续账户和 2024 跨年训练；仅生成 daily/fund_flow 两个 Parquet。历史矩阵 26,009,973 字节，488 个 bundle 合计 25,935,534 字节。第二成本的目标和诊断必须与第一成本完全相同；22 个账户原生结果完整，核账残差小于 0.00001 元。

只读取了原 manifest 的覆盖元数据：daily 4,017,047 行、fund_flow 3,865,427 行，范围包含 2021-10-08 至 2024-12-31。未打开任何真实 Parquet 数值；未来读取仍排除 2021 数值 warmup。按 daily 总行数与 44,000 合成股票日简单线性放大，比例约 91.3；仅历史 JSON/bundle 约 4.74 GB。这是包含不准读年份的保守规模参照，不是已测得的实际磁盘需求或运行时间；还不包含 Python 对象、原始读入、模型、账户与瞬时拷贝。内存峰值尚未测准，不能据此直接全量启动。
