3. 启动前核验 Issue184 上的实际预登记评论和资源条件，再独占创建跨工作树共享的一次性记录。22 个原生账户 Trial 必须全部登记后才能开始数值工作。失败保留完整预算和实际登记数，不自动重跑。
4. 回测和独立审计使用分开的受限子进程。沿用每阶段最多 4 小时、进程私有内存上限 10 GiB、系统可用内存下限 4 GiB；真实负载能否完成须由实际监督记录证明。

6. 父进程确认真实子进程退出、完整原生结果及文件哈希后才进入审计。结果、数据库和审计不可覆盖；独立审计通过后另存 `ASSESSMENT.json`，仍明确 `validated_alpha=false`、统计检验 NOT_RUN。

这是单用户研究完整性保护，不是多用户身份系统或操作系统安全沙盒。

## 使用顺序

从通过当前提交测试和全部必需 CI 的干净专用工作树运行：

```text
python scripts/run_flow_response_continuation.py prepare --output artifacts/flow-response/checkpoints/continuation-plan.json
```

核对完整计划并在 Issue184 预登记其规范 SHA-256、完整 22 项预算和固定研究契约，再用实际评论 ID：

```text
python scripts/run_flow_response_continuation.py run --plan artifacts/flow-response/checkpoints/continuation-plan.json --preregistration-comment <actual-comment-id>
```

这不是现在已经获准重复消耗历史实验的命令。旧 002/003/B17 启动器不得重跑。若新的共享记录已存在，先检查运行状态，不得换输出目录或删除记录来绕过一次性限制。
