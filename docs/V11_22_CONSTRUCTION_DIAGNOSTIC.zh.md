# V11.22：组合构造诊断

本版本回答：同一合格股票截面上，分层选股与全局选股的构造差异，是否是高换手和净收益损失的重要来源？它不是新的 Alpha 主候选，也不是为旧失败信号降低标准。

## 冻结设计

| 项目 | 唯一允许的定义 |
| --- | --- |
| 新账户 | global_lowvol / global_hash，各 82、164 bps，共 4 个 |
| 选股 | 全局前 40；旧名单仍处于前 60 时保留；不足留现金 |
| 哈希 | 延用 `v11.21:184:<name>`，不换种子 |
| 支持集 | 原日 K、资金流快照及已审计历史矩阵；同日 8 个有限特征共同支持集 |
| 信号与交易 | 前一交易日信号；20 个全局交易日；0/5/10/15 四相位 |
| 资金 | 单个连续 300 万元账户，跨年不重置，四组目标合并净额执行 |
| 执行 | 原 target_changes、容量、停牌/涨跌停、核销恢复与成本模型不变 |
| 观察窗口 | 原 2023–2024 开发窗口；不读 2025/2026，不引入新来源 |
| 旧对照 | 已完成的 lowvol/hash 双成本 4 账户只读复用，不再执行 |
| 新拟合 | 0；不重拟合原 14 个模型或历史提供者 |
| 试验计数 | 启动前实际下界 3729；占用完整新预算后 3733；失败也保留 |

每个相位最多 40 只不等于实际合并账户始终只有 40 只。名单替换率不是成交金额换手率。全局构造同时改变风险分布和名单保留，不能把差异解释成单一变量的因果效应。

## 已实现的链路

1. 保留 B22 原始提交、代码字节、原生结果、共享终态和独立审计；不拿新 HEAD 重建旧计划。旧代码文件的内容与 Git 历史都必须不变，新增模块不会覆盖旧归档。
2. `prepare` 只绑定已完成结果、实际文件哈希和日期覆盖；新市场数值计算前，核验 Issue #184 的准确 V11.22 计划登记，独占共享 claim，并原生登记全部 4 个账户。
3. 生产阶段读取一次已验证的不可变历史矩阵，输出完整目标、账户、费用、成交和现金/持仓轨迹。记录每次换仓的新名单数量、选中波动率均值和 20 个原始分层单元的数量。
4. 独立阶段重新核验来源到历史特征，单独实现全局排序/保留/四相位合并，再核对已保存的成交、费用、股份和净值。不调用生产选股器、组合器或执行器作为独立证据。
5. 生产与审计分进程顺序监督：每阶段最多 4 小时、私有提交内存 10 GiB、空闲物理内存至少 4 GiB。退出、失败和资源拒绝均保留，禁止自动重入或换输出目录重跑。

这是单用户研究完整性机制，不是多用户权限或 OS 安全沙箱。原始数据、结果和本机路径均留在忽略目录，不提交 Git。

## 验证与启动约束

快速合成测试覆盖 top60 边界、相位与跨年连续性、未来值不影响过去、缺失支持集留现金、原生全额登记、代码/快照/账户被篡改的拒绝、失败债务与重复启动拒绝。端到端测试复用已有合成源，真正执行四账户及独立来源/目标/账户审计；操作系统资源监督在编排测试中模拟，其实际实现另有测试。

首次端到端测试发现一处测试断言字段名错误（把 `source_history_audit_pass` 写为 `pass`）；账户与数值审计已经完成，修正断言后必须重新执行测试，而不是把该次运行标绿。

只有本提交完整 CI 三组全部通过、工作树干净、实际计划与哈希完整登记后，才允许启动一次真实诊断。设计文档、工程进展评论和合成测试结果都不是实证计划登记。运行入口是 `scripts/run_portfolio_construction.py`；没有成本、年份、种子或股票池参数。

## 结果解释和后续

输出全部 4 个新账户与 4 个固定旧对照的分年/全期净收益、Sharpe、最大回撤、费用、成交、现金和风格/名单变化。不加回费用冒充零成本再回测，不挑单年或单成本赢家。

统计状态固定 `NOT_RUN_DIAGNOSTIC`，DSR/PBO/placebo 为 null，`validated_alpha=false`。完整审计成功只能叫 `COMPLETE_DIAGNOSTIC_AUDITED`，不能叫 Alpha Court PASS。

如果构造影响显著，下一有限预登记研究应分离风格配置、风格内信号和持仓维护，再检验信号增量；影响不明显则保留负结果并换机制。任何新策略/方向/成本变体继续计入总试验记录。可用 Alpha 仍需独立证据、全部历史多重试验、原 DSR/PBO/placebo 与路径/容量门槛；反复使用的开发年份不能当首次样本外验证。
