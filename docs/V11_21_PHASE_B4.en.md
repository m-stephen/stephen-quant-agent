## Implementation and evidence limits

1. `flow_response_protocol.py` freezes candidate packet,23-item budget,controls,costs and screen. JSON roundtrips preserve canonical hashes. Changed budget,debt,cost,calendar,packet or tombstones fail before database creation.
2. Cross-cost sharing completes both annual source fits, then binds those same actual files to the other cost Trial. Contracts may differ only in account name/cost. Native timing,actual model bytes,history and calendar are checked. Two bindings are not two independent fits.
3. `VerifiedHistoryCache` decodes one bound history per process into recursively immutable mappings/tuples. Each use still verifies source relationships,actual history bytes and all bundle SHA-256 values. Arbitrary caller `.get()` objects are rejected. This reduces JSON parsing, not all hash I/O, and is not a multiuser security system.
4. Original lowvol/stable target files are verified against the original card and actual/canonical digests, then copied byte-for-byte. Tests use synthetic originals; no actual old-target values were read. Old targets use full_target; new policies use target_changes. All use disclosed conservative B3 bars, so this is not a claim of identical historical account results.
5. `audit_response_account` independently reconstructs shares,fees,cash,close/stale/writeoff marks,NAV,annual returns and Sharpe without invoking execution,target-generation or return-summary functions. Adversarial time,fill,cash,cost,mark,limit and capacity changes fail. It does **not** independently prove raw-source correctness,model training,target selection or target_changes scheduling; that limitation is explicit.
6. `workflows/flow_response_epoch.py` connects native-spec verification,exclusive backend marker,original anchors,history,14 fits/28 bindings,22 accounts and exclusive RESULT output. Failure preserves all reservations plus ABORTED; replay cannot overwrite evidence. It is not a production launch authorization: global cross-operation claims,fixed parent/runtime evidence and GitHub preregistration still require the outer entrypoint.
7. Even attractive account numbers remain `COMPLETE_PENDING_INDEPENDENT_AUDIT`,with source/model/target audit NOT_RUN and validated_alpha=false. DSR/PBO/placebo remain null/NOT_RUN.
