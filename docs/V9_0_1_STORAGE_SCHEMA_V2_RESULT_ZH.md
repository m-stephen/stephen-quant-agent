# V9.0.1 分钟存储 Schema V2 基准结果

状态：**核心分钟 Schema 门禁通过；Issue #160 仍在进行中。**

## 设计

- 物理 Parquet 不再逐行保存 `revision_id`、`effective_at`、`available_at`。
- `effective_at = bar_at`、`available_at = bar_at + 1 second` 由兼容视图恢复。
- `revision_id` 由业务字段与来源成员身份确定性生成；当前版本的选择顺序使用批次时间与来源身份，不强制扫描时计算 SHA-256。
- 新旧 Parquet 可以混合读取；原始来源哈希、成员路径、成员哈希、批次时间及快照哈希继续保留。

## 真实数据双写基准

| 范围 | 行数 | V1 | V2 | 体积下降 | 查询变化 | 数据指纹 |
|---|---:|---:|---:|---:|---:|---|
| 2000 年完整 5 分钟年度归档 | 5,571,408 | 247.45 MiB | 55.56 MiB | 77.55% | +2.45% | 一致 |
| 2009–2026 跨年 1 分钟归档 | 101,858,903 | 5.00 GiB | 1.06 GiB | 78.74% | +8.54% | 一致 |
